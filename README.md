# Proxy Bot для Telegram

Сайт: https://autotgproxyantidpi.onrender.com/  
Бот: https://t.me/autotgproxysuperbot

Сервис собирает публичные MTProto-ссылки и проверяет их настоящим TDLib `testProxy`.
Сайт и бот используют общий подбор: основной вариант, доступные резервы, место и время
измерения. Подтверждение действует пять минут. Открытый TCP-порт, SNI, отзывы и ручное
закрепление не заменяют протокольную проверку.

Основной сервер находится в Орегоне. Его результат не подтверждает доступность у
российского оператора. Для этого предусмотрен частный проверяющий агент в реальной
домашней или мобильной сети РФ. Без подключённого агента интерфейс честно показывает
только проверку из Орегона. Пользовательский Telegram-трафик через сайт не проходит.

Доступ бесплатный, платежей нет. Главная, кабинет, документы и админка используют общую систему оформления со светлой, тёмной
и системной темами. Шрифт Onest и GSAP подключаются локально. Бот использует короткие сообщения,
блоки результатов проверки, выделенную кнопку подключения и меню навигации.

## Локальный запуск

Нужны Python 3.11+ и PostgreSQL. Библиотека TDLib устанавливается пакетом `tdjson` из
`requirements.txt`; Telegram-аккаунт, `api_id` и `api_hash` для проверок не нужны.

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env`, затем:

```powershell
.venv\Scripts\python.exe -m app.proxy.tdjson_helper --self-test
.venv\Scripts\python.exe main.py
```

Без `BOT_TOKEN` работает сайт, без `DATABASE_URL` недоступны аккаунты и удалённые агенты.
Локально с пустым `BASE_URL` бот использует polling. На публичном HTTPS-адресе используется
webhook с отдельным секретом. Миграции применяются при запуске.

## Настройка сервера

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN`, `BOT_USERNAME` | Токен от `@BotFather` и имя того же бота без `@`. |
| `DATABASE_URL` | Строка подключения PostgreSQL; для Render используйте внутренний адрес БД в том же регионе. |
| `SECRET_KEY` | Постоянный случайный ключ сессий, минимум 32 символа для HTTPS. |
| `BASE_URL` | Публичный HTTP(S)-адрес без пути; на Render возможен `RENDER_EXTERNAL_URL`. |
| `TG_WEBHOOK_SECRET` | Отдельный секрет webhook; при отсутствии выводится из ключа приложения. |
| `ADMIN_PASSWORD`, `ADMIN_PATH` | Пароль и путь админки. Без пароля вход отключён. Путь содержит буквы, цифры, `_`, `-`. |
| `PROBE_AGENTS_JSON` | Список заранее разрешённых частных агентов. По умолчанию `[]`; пример в инструкции подбора. |
| `TRUSTED_PROXY_HOPS` | По умолчанию `0`: forwarded-заголовки не определяют IP. Меняйте только для известной цепочки доверенных reverse proxy. |

Ключ можно создать командой `py -c "import secrets; print(secrets.token_urlsafe(48))"`.
Для каждой роли используйте отдельное значение. `.env`, ключи и артефакты тестов исключены из Git.

В `.env.example` также перечислены интервалы, размер каталога, источники и необязательный
`TDJSON_LIBRARY` для собственного доверенного файла TDLib. `FETCH_PROXY` влияет только
на скачивание списков; проверка MTProto идёт напрямую из сети узла. Отключения TLS-проверки нет.

## Развёртывание на Render

`render.yaml` описывает один постоянно работающий Web Service в Орегоне:
сборка `pip install -r requirements.txt`, запуск `python main.py`, health-check `/healthz`.
Один экземпляр нужен для общего кэша сайта и бота, локальных лимитов и реестра админских
сессий. Постоянные измерения и задания агентов хранятся в PostgreSQL.

Задайте переменные в Environment и публичный HTTPS-адрес. После обновления проверьте
самопроверку TDLib и состояние узлов во вкладке «Инструменты». Старые восьмизначные ID
не получают новое подтверждение: сборщик создаст точные варианты с новым секретом и
измерит их заново. Ручное исключение сохраняется при повторном сборе.

Доступность самого домена сайта из России проверяется отдельно. Успешный health-check
на хостинге не доказывает, что российский пользователь открывает этот адрес.

## Документы в подвале

Общедоступные страницы `/legal/privacy`, `/legal/terms`, `/legal/cookies` и
`/legal/selection` открываются без входа и без JavaScript приложения. Они описывают
персональные данные, бесплатное использование, техническое хранение и правила подбора.
Форма регистрации ссылается на условия и политику; просмотр сайта не объявляется согласием.

Заполните фактические значения `LEGAL_*` из `.env.example`: владельца, почтовый адрес,
контакт по данным, расположение базы, поставщиков обработки и сроки журналов/резервных
копий. ИНН и ОГРН/ОГРНИП указываются, если применимы. До заполнения сведений документы
помечены как проекты. Указание значений в окружении меняет текст документов, а не
инфраструктуру, сроки удаления или юридический статус сервиса.

[Заметки о требованиях РФ и размещении в Орегоне](docs/legal-deployment.md).

## Проверки

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Для транзакций, конкурентных leases и миграций укажите `TEST_DATABASE_URL` тестовой
PostgreSQL. Тесты создают отдельную схему на каждый сценарий и удаляют только её.

```powershell
$env:TEST_DATABASE_URL='postgresql://test_user@127.0.0.1:5432/test_db'
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe tests/frontend_smoke.py
```

Браузерный сценарий использует установленный Chrome и тестовые репозитории: проверяет
ширины 320/390/768/1440, обе темы, основной вариант с резервом и инструменты админки.
Скриншоты сохраняются в `build/ui-preview`. Рабочие токены и production-БД не нужны.
